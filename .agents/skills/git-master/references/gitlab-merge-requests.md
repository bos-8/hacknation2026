# GitLab Merge Requests

- Confirm instance/project, source/target branches and the complete diff; reuse
  a matching open MR when appropriate.
- Describe the resulting behavior, actual validation and material limitations.
  Use [Messages](./messages.md) for commit/squash titles when needed.
- Check pipeline status, approvals, discussions, conflicts and protected-branch
  policy. Merge only when authorized and the applicable requirements are met.
- Report the MR URL and actual state. Do not equate an accepted push with a merged
  MR, published release or successful deployment, or weaken protections to proceed.
