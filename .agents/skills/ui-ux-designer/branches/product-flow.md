# Product Flow

Design interfaces around user goals, workflow efficiency, visual hierarchy, and implementation constraints.

## Trigger

Use when the task involves:

- UI/UX design, frontend screens, components, flows, dashboards, forms, or navigation;
- improving visual polish, layout, hierarchy, spacing, typography, or interaction states;
- making interfaces responsive, accessible, or easier to scan;
- turning a vague product idea into a usable first screen.

## Workflow

1. Identify the user role, core job, and primary workflow.
2. Define layout, information hierarchy, controls, empty/loading/error states, and responsive behavior.
3. Implement with existing components and tokens when available.
4. Validate that text fits, controls are usable, and key states are reachable.

## UI Rules

- Use familiar controls: buttons for commands, tabs for views, toggles for binary settings, sliders/inputs for numeric values, menus for option sets.
- Use icons for common tool actions when an icon library exists.
- Keep page sections unframed; use cards only for repeated items, modals, or genuinely framed tools.
- Avoid decorative noise that does not help the task.
- Keep compact UI text proportional to its container.
- Do not let text overlap or resize layout unexpectedly.
- Use stable dimensions for fixed-format boards, toolbars, tiles, and counters.

## Product Fit

- Operational SaaS/admin tools: restrained, dense, scannable, repeat-use focused.
- Games/creative tools: more expressive, animated, and playful when appropriate.
- Branded/product/venue pages: show the product/place/object immediately in the first viewport.
